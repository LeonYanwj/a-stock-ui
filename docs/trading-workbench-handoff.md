# A 股交易后台：前端设计交接

> 本文是交易后台前端改造的唯一设计依据。后端的接口、账务规则和数据语义以 `a-stock-analyzer/API.md` 及交易实例接口为准；不要从旧 `paper_*` 页面推断新交易流程。

## 1. 要做的页面

面向在华泰证券手工执行的交易者，提供一个可见、可解释的执行后台。用户只需要理解以下路径：

```text
启动本次交易 → 查看市场扫描与候选池 → 看今日计划并在华泰下单
→ 在同一计划行回填真实成交 → 查看持仓、盈亏和动作历史
```

不要在 UI 中展示“交易实例”、“影子体系”、“任务锁”、“策略版本 ID”等实现术语。策略版本和数据截面仅在计划详情的“数据与依据”中按需展开。

## 2. 视觉方向（已确认）

整体采用 Vetra 式明亮、柔和的后台风格，但不得复制其品牌、源码、图标、插画或页面素材：

- 白色固定左侧栏：品牌、当前用户/当前交易、简洁导航；
- 浅紫灰页面背景，白色圆角信息卡片，适度的柔和阴影；
- 珊瑚色作为“启动本次交易”等唯一主操作色；
- 图表、状态和表格保持轻量、留白充足，避免深色交易终端和密集专业面板；
- 采用系统中文无衬线字体；数据列使用等宽数字；
- 所有桌面布局在窄屏时改为单列，关键计划表可横向滚动但不得截断状态。

### 色彩 token

| 名称 | 值 | 使用位置 |
|---|---:|---|
| `page` | `#F8F7FF` | 页面底色 |
| `surface` | `#FFFFFF` | 侧栏、顶栏、卡片 |
| `ink` | `#312C46` | 标题、主要信息 |
| `muted` | `#9490A5` | 辅助文字、时间、数据状态 |
| `primary` | `#F1846D` | 主按钮、当前导航、关键待办 |
| `primarySoft` | `#FFF0EC` | 当前导航、弱强调背景 |
| `success` | `#6CCBA7` | 正常、已完成、可执行 |
| `warning` | `#F6BD4F` | 等待确认、行情延迟 |
| `danger` | `#D95F55` | 被阻止、风险与错误 |

## 3. 导航与页面职责

```text
概览
当前交易
市场扫描
持仓与记录
交易规则
设置
```

### 概览

展示本次交易状态、资金与仓位摘要、今日执行进度、今日操作摘要和“交易路径”四步状态列：

```text
启动交易 → 扫描与候选池 → 华泰成交回填 → 持仓与复盘
```

未启动时只展示真实空状态与“启动本次交易”按钮；不填充示例股票、示例价格或示例收益。

### 当前交易（核心页）

每一条真实计划用一行或可展开卡片展示，并在同一位置完成实际成交回填：

- 证券代码、名称、资产类型；
- 入选理由、信号时间、数据状态；
- 建仓/加仓/减仓/清仓、建议数量、目标仓位；
- 参考价、允许价格区间、失效条件、有效期；
- 华泰报价确认、实际成交价、数量、时间、费用和未成交原因；
- 当前成本、持仓、浮动盈亏，以及完整动作历史入口。

不得另建一个重复的“成交回填”页面。未确认报价时，保存按钮禁用并明确说明原因；回填成功后同页刷新持仓、成本和盈亏。

### 市场扫描

展示系统为什么从市场中选出标的：扫描范围、`as_of` 数据截面、最近扫描时间、数据状态、候选池增减、入选理由与淘汰理由。

仅当 ETF 数据已准备好时才显示 ETF；数据不足、过期、扫描失败或无符合标的必须明确显示原因，不能显示空白。

### 持仓与记录

只读取真实成交派生的持仓。按证券显示数量、成本、最新价、浮动盈亏和最近动作；展开后显示建仓、加仓、减仓、清仓、费用及计划/成交偏差。

## 4. 数据状态必须可见

| 后端状态 | 前端表达 | 用户下一步 |
|---|---|---|
| `draft` | 尚未启动 | 点击启动本次交易 |
| 计划生成中 | 正在扫描/形成候选池/生成计划，显示阶段与开始时间 | 等待或查看失败原因 |
| 无计划 | 无符合标的、数据不足或风控阻止 | 查看原因，不伪造股票 |
| `eligible` | 可执行，但可能需确认华泰报价 | 确认报价后在华泰下单并回填 |
| `blocked` | 明确风险码、缺失数据和恢复建议 | 修复数据或不执行 |
| 部分/全部成交 | 实际成交、仓位、成本和偏差 | 完成剩余计划或进入复盘 |

所有加载、错误和空状态都必须有文字说明。页面只能呈现 API 返回的真实数据；不要用 mock 数据伪装当前交易。

## 5. 前端的数据来源

优先复用现有 `src/lib/api.ts` 和 `src/types.ts` 中的交易实例封装：

```text
GET  /api/dashboard
GET  /api/trade-runs
GET  /api/trade-runs/{runId}
GET  /api/trade-runs/{runId}/dashboard
GET  /api/trade-runs/{runId}/plans
POST /api/trade-runs/{runId}/fills
GET  /api/trade-runs/{runId}/positions
GET  /api/trade-runs/{runId}/performance
GET  /api/trade-runs/{runId}/events
```

如 UI 所需字段当前 API 未返回，前端先用明确的“数据暂未提供”状态；将字段缺口列入后端改造清单，不能在前端自行计算或伪造。

## 6. 推荐落点

| 前端位置 | 责任 |
|---|---|
| `src/components/layout/app-shell.tsx` | Vetra 风格侧栏、顶栏与全局色彩层级 |
| `src/pages/orbit-dashboard.tsx` | 改造成概览和交易路径入口，或拆出新的 `trade-workbench-page.tsx` |
| 新的 `src/pages/trade-workbench-page.tsx` | 当前交易、成交回填、持仓/动作抽屉 |
| 新的 `src/pages/market-scan-page.tsx` | 候选池、扫描截面、数据状态和理由 |
| `src/lib/api.ts`、`src/types.ts` | 仅补足契约字段，不在组件中直接请求或拼装 API |
| `src/styles.css` | 设计 token、状态颜色和响应式规则 |

## 7. 验收

1. 一眼看上去是明亮柔和的后台系统，而不是深色交易终端或默认 shadcn 卡片拼接。
2. 用户可以在一个“当前交易”页面内完成看理由、在华泰执行和回填成交。
3. 每只真实股票能追溯原因、动作、数量、价格区间、成交、成本、盈亏和动作历史。
4. 空状态、延迟数据、失败、无标的和风控阻止都有明确且可执行的提示。
5. 不显示影子体系，不复制 Vetra 的品牌、代码或素材，不伪造真实交易数据。
